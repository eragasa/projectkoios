# UC-02: Evidence-grounded manuscript and course-note development

## Record status

- **Identifier:** `UC-02`
- **Definition status:** Draft
- **Observed basis:** bounded manuscript authoring with an independent
  reference-grounded course explanation
- **Architecture:**
  [evidence-grounded long-form authoring](../architecture/v0/index.md#evidence-grounded-long-form-authoring)
- **First prototype:** one `ksdft2effmass` manuscript subsection
- **Independent reuse test:** one reference-grounded course explanation
- **Parent roadmap:** `RAG-ROADMAP-01`

This record does not authorize source access, implementation, manuscript edits,
course changes, model execution, publication, or release.

## Goal

An author asks for help with one bounded passage and receives a short proposal
grounded in inspectable evidence from multiple references. The author can see
which evidence led to each proposed citation, what is unsupported, and where
sources disagree.

The first prototype ends at a reviewable local proposal. It does not
automatically edit the target.

## Independence from other use cases

UC-02 is not downstream of UC-01 and does not require the textbook use case to
complete first. The two use cases may reuse admitted source evidence and
retrieval boundaries without creating an execution dependency.

## Actors and authority

- **Author or principal investigator:** selects the writing need, authorizes
  purpose-specific local use, and decides scientific and editorial acceptance.
- **References owner:** records bibliographic identity/status, observed assets,
  reference-to-asset linkage, and access/rights evidence; it does not authorize
  use.
- **Ingestion owner:** produces extraction/transcript records with page/block
  lineage; it neither attaches references nor writes prose.
- **Search owner:** composes and retrieves bounded evidence items; it does not
  decide claim support.
- **Domain composer:** retains target context and proposes text/citations from a
  bounded evidence bundle.
- **Repository-local checker:** reports implemented structural problems without
  claiming content is correct.

## Preconditions

1. The target passage has an exact revision identity and remains read-only.
2. Each selected work has explicit bibliographic authority status, an observed
   asset/linkage, and an exact asset identity.
3. The author or domain owner has explicitly authorized the selected asset for
   this local purpose. Unknown rights or missing authorization stops before
   ingestion.
4. Canonical transcript blocks pass lineage checks and resolve to retained
   extraction text, transformations, and block-specific warning details.
5. The authoring owner has judged the selected evidence fit for this bounded
   use; a passing audit or warning count alone is not that judgment.
6. The target text and generated prose are excluded from the source-evidence
   index.
7. The prototype uses local inference; source and target text are not sent to a
   remote model provider.
8. The model has no tools and cannot act on instructions found in retrieved
   text.
9. No write or publication authority is implied.

## Manuscript prototype

### Trigger

The `ksdft2effmass` author selects one passage or planned subsection and asks a
specific question, for example:

- Which sources support this statement?
- How do these sources define the same quantity?
- Where do their assumptions or conventions differ?
- Is this claim broader than the available evidence?
- Can the system propose a clearer evidence-grounded paragraph?

### Main flow

1. The `ksdft2effmass` prototype composition reads the selected manuscript file
   and admitted reference evidence without modifying either.
2. It records the exact manuscript revision and selected source span.
3. It retains bounded manuscript context locally and sends Search only a
   bounded query representation, `manuscript_authoring` purpose, opaque target
   identity, optional bibliographic-work filters, and fixed bounds.
4. Search runs deterministic lexical retrieval over admitted reference evidence
   only.
5. Each evidence item identifies the bibliographic work and authority status,
   selected asset, transcript result, page, clean-transcript block record,
   retained source spans, indexed text, retained extraction text or mapping,
   warning details, and deterministic evidence-item identity.
6. Search orders candidates by lexical score then evidence-item identity,
   retains the strongest eligible result, and fills remaining slots while
   applying a per-bibliographic-work cap.
7. Search returns exact corpus/index identity, ranks, tie keys, applied bounds,
   omissions, warnings, and one closed outcome.
8. If a valid completed search selects no eligible item, it returns
   `INSUFFICIENT_EVIDENCE`. Invalid input and infrastructure failure remain
   distinct.
9. The domain composer gives the local model only the bounded manuscript
   context and evidence bundle.
10. The model proposes one paragraph or short subsection containing:
    - proposed text;
    - presentation markers linked to stable evidence-item identities;
    - every material statement lacking adequate evidence marked unsupported or
      partial;
    - visible conflicts and qualifications; and
    - bibliography gaps.
11. For each proposed citation, the proposal reports any accepted canonical
    citekey supplied by References and its target status: accepted,
    prospective, or missing. A candidate/proposed key is never emitted as an
    accepted citation.
12. Validation checks that every citation marker maps to a supplied evidence
    item and every exact quotation resolves to retained extraction text or an
    explicit transformation mapping.
13. The author sees indexed text, retained extraction, warnings, page locator,
    citation-key status, and proposed prose together.
14. Stop. The author manually copies, revises, or rejects the proposal.

The first slice does not need an automated patch applier, review database,
workflow engine, API, or browser interface.

## Evidence shown to the author

Each evidence entry shows:

- stable evidence-item identity and presentation label;
- bibliographic work identity and candidate/accepted status;
- optional accepted canonical citekey;
- observed source-asset and transcript identities;
- page identity/index and printed label when available;
- clean-transcript block identity and retained source spans;
- indexed clean text and exact retained extraction text;
- extraction/transformation warnings;
- lexical score, rank, and tie key; and
- omissions caused by per-work or aggregate bounds.

“Exact” here means exact relative to retained extraction output, not guaranteed
correct relative to rendered PDF ground truth. Page evidence and warnings remain
available for inspection.

Bundle-local labels such as `E1` are display aids, not durable identities.

## Proposal shown to the author

A proposal is readable without hidden chat history. It contains:

- opaque target identity plus target revision/span retained by the domain owner;
- the author's writing question;
- proposed text;
- citation markers mapped to stable evidence-item identities;
- accepted/prospective/missing target citekey status;
- unsupported and partial statements;
- conflicts and source-specific conventions; and
- model and prompt identity sufficient to inspect the run.

Citation resolution establishes only that referenced evidence exists. It does
not establish entailment or scientific correctness.

## Search outcomes

- `EVIDENCE_AVAILABLE`: one or more eligible items were selected.
- `INSUFFICIENT_EVIDENCE`: a valid completed search selected no item under the
  declared lexical, filter, and bound rules, or an explicitly required work was
  absent.
- `INVALID_REQUEST`: bounds, purpose, filters, or requested capability are not
  supported.
- `INFRASTRUCTURE_FAILURE`: the index or retrieval operation could not complete.

A reviewer deciding that available evidence does not support the claim is a
human review result, not Search insufficiency. Unexpected defects are never
converted to insufficiency.

## Failure behavior

### Source admission is unresolved

Report the specific typed failure: `REFERENCE_IDENTITY_UNRESOLVED`,
`DISCOVERY_INCOMPLETE`, `ASSET_INACCESSIBLE`, `RIGHTS_UNKNOWN`,
`USE_NOT_AUTHORIZED`, or `INGESTION_MISSING`. Stop before retrieval and do not
relabel the failure as Search insufficiency.

### No lexical evidence

Return `INSUFFICIENT_EVIDENCE`. Do not draft a literature-backed claim.

### Missing intended work

Report the missing work. Do not silently substitute another reference.

### Partial support

Mark the affected statement partial and propose narrowing it.

### Conflicting sources

Show both works and their conventions. Do not silently merge or choose a value.

### Warning affects selected evidence

Require page inspection or exclude the item. Baseline warning presence and
warning count alone neither admit nor reject evidence.

### Equation representation is required

The text-only prototype may use inspectable retained prose about an equation.
If the claim requires symbolic reconstruction, rendering, or equivalence,
report deferred modality and generate no equation-backed prose.

### Prompt-like instructions appear in retrieved text

Treat them as quoted source content. The model has no tools and the system
ignores requests to change policy, access data, or perform effects.

### Target changed during the run

Mark the proposal stale and require a new run or explicit manual comparison.

### A structural checker passes

Continue to human review. Do not claim mathematical, scientific, editorial, or
pedagogical correctness.

## Optional structural check

The prototype does not assume that a repository-local LaTeX auditor currently
exists. If one is present at prototype time, apply only its documented
implemented checks to a staged copy. Possible checks include include
containment, missing includes, duplicate labels, and unresolved references.

Bibliography validation remains separate. Every proposed citation marker must
map to bundle evidence, and every proposed target key must resolve or remain an
explicit gap. Bibliography presence does not establish source support.

## Reference-grounded course reuse test — Courses Option A

After the manuscript prototype is useful, run one separate course-owner case.
The course author selects:

- one stable learning-objective identity with exact text/revision;
- one bounded note revision/span;
- a small independent-reference corpus containing expected theory; and
- at least one excluded example or solution passage.

`lecture_authoring` is default-deny and admits only independently validated
`theory_evidence` from independent references. There is no cross-purpose
fallback. Existing course notes, worked examples, exercises, model answers, and
every source/generated/reviewed solution role remain owner-local context and
are not Search evidence in this slice.

The learning-objective identity/text/revision stays in course target context and
proposal provenance. Search neither owns nor infers it. The output is one
bounded explanatory prose block. The course author records whether it aligns
with the objective and how much revision it needs.

This is a reference-grounded test, not full integration of atomic notes. It
tests whether evidence items, retrieval, citation mapping, insufficiency, and
conflict behavior are independently reusable without forcing manuscript and
course policy into one abstraction.

## Small benchmark

Fix these cases before evaluation:

1. a directly supported claim;
2. a paraphrased question;
3. a partially supported claim;
4. conflicting works;
5. a missing intended work;
6. an equation-oriented question answerable from retained text;
7. an equation request requiring deferred modality;
8. a deliberately zero-hit lexical request; and
9. the course case with admitted theory and an excluded example/solution.

Inspect whether expected evidence appears, source locators and retained
quotations resolve, ranking replays, every citation uses supplied evidence,
unsupported material stays visible, excluded course roles remain excluded, and
the author finds the proposal useful without excessive revision.

Passing this benchmark demonstrates a useful software slice, not scientific or
pedagogical validation.

## Acceptance for the manuscript prototype

The first slice is complete when:

1. source and manuscript inputs remain unchanged;
2. source/use admission and transcript lineage gates fail closed;
3. the manuscript cannot retrieve itself as evidence;
4. each selected item resolves to exact retained extraction and page/block
   lineage;
5. retrieval ordering and multiple-work selection replay deterministically;
6. every proposed citation maps only to supplied evidence;
7. every material factual statement not mapped to adequate evidence is marked
   unsupported or partial;
8. target citekeys resolve or remain explicit gaps;
9. missing, conflicting, deferred-modality, and zero-hit cases remain distinct;
10. no private path or protected excerpt appears in public outputs;
11. no automatic target or bibliography write occurs; and
12. the author can assess the proposal without hidden session context.

## Sharing gate

Keep the manuscript composer in `ksdft2effmass` and the course composer in
`projectkoios-courses` during their first slices. Reusable owners never import
those domain repositories.

Extract shared generation behavior only if both prototypes independently need
the same bounded evidence input, citation mapping, insufficiency/conflict
behavior, and proposal/write separation. Target parsing, objective handling,
scientific policy, pedagogical policy, domain checks, and acceptance remain
local.

## Out of scope

The prototype excludes autonomous long-document writing, direct model edits,
automatic bibliography mutation, scientific or pedagogical acceptance,
semantic or typed-equation retrieval, persistent review workflows, API/Web,
model training, cloud transmission of private content, publication/deployment,
and shared generation infrastructure extracted from one consumer.
